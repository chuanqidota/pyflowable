```
flowable流程的英文名称和类名称，任务名称和类方法名称做映射
代码驱动flowable的流程往前走
```

#### 项目如何在本地运转

```
step1:
 部署一套 PostgreSQL;本文只提供单机mac版的方式，并设置.env文件
step2:
 docker-compose.yaml只包含flowable和redis
 通过docker compose up -d启动
step3:
 启动本项目python manage.py runserver
```

#### 从零测试步骤
```
1、安装pg,并初始化(参考mac系统上安装pg.md)
2、启动docker-compose up -d；然后导入流程示例里面的xml
3、在mysql数据库上创建库pyflowable
4、pip install -r requirement
5、执行python manage.py migrate
6、执行 python manage.py create_user '{"username":"admin","name":"admin","password":"admin","is_admin":True}'
7、执行 python manage.py runserver
8、浏览器访问 http://127.0.0.1:8000
9、输入用户名和密码 admin;admin
10、创建用户分组、创建用户、创建流程分组、创建流程、提交工单、审批工单、认领工单、处理工单

以应用申请为例
11、提交工单-(下一个节点为领导审批)
12、领导审批-(在代办中可以看到工单)
13、处理工单-(下一个节点为SOR处理，会掉到工单池中)
14、认领工单-(这个任务绑定的用户组的成员可以认领工单)
15、处理工单-(在我的代办中可以看到刚刚认领的工单,进行处理)
```

#### 后续代码编写方法
```
1、在flowable上面创建流程,参考流程示例里面的流程
2、flowable的流程key和process下面的流程文件的类名称一致，flowable里面的任务名必须以_task结尾，和process下面类里面方法名称一致
3、调用接口创建flowable的流程分组/流程定义(key和上述key保持一致)/创建流程属性
4、准备好以后编写业务代码,然后就可以各种工单操作
5、装饰器
   @finish_task 除最后一个任务上,别的任务上都需要有
   @complete_task 只放在最后一个任务上
6、流程驱动:
   每个任务的返回值
   1、下一个任务节点是审批节点
   2、下一个节点是网关节点
        同意：下一个节点可以让其自动执行，或者指明下一个节点的审批人
        驳回：回到那个节点上，清楚哪些节点，指明下一个节点的审批人
   3、自动执行节点
```
